# Human in the Loop — 重新接上项目

## Outcome

让人和下一次 AI 共用根目录的 `evidence.md`，快速知道当前目标、上次证实了什么、还有什么未解决、从哪里继续。人可以只看，也可以随手写；AI 负责核对、整理和维护，让人的体验与取舍持续影响工作。

记录保持四个字段，以能直接读懂为先。它保存当前工作的可信接续点；是否降低切换项目的负担，要在真实使用中判断。成功包括更新、无需更新和目标已完成，不为维持循环制造新任务。

## Use when

- 回到一个已选项目，说“忘了做到哪”“帮我接上这个项目”。
- 准备暂停、交接或切换会话，希望留下可以核实的当前进展。
- 希望将实际验证结果、未解决问题、人工反馈或随手简记带到后续工作。
- 显式调用 `$human-in-the-loop`，或明确要求维护项目的 `evidence.md`。

## Do not use when

- 尚未选定项目或任务，需要从待办中决定做什么；这属于 `todo`。
- 普通实现请求没有接续或记录需求；不自动给所有开发任务加检查点。
- 需要完整日志、待办清单、项目管理系统、定时提醒、后台监控或逐步审批。
- 需要完整的 Agent 安装运行指南或 GEO 内容优化；仅帮助后续 Agent 找到证据的指引可作为本流程的接入细节。

## Inputs

- 必需：一个可确定的项目和当前任务。优先使用当前请求、会话和项目记录，无需用户重新填表。
- 可选：随手写的中英文片段、验收反馈、刚发生的结果、暂停或继续意图、项目路径。
- 默认：显式路径，其次当前 Git 根目录，否则明确的当前项目目录；唯一根记录 `evidence.md`；英文标签、用户语言的正文。用户只问状态或要求只读时，仅回答，不写文件。
- 调用授权有界的记录维护，不授权执行记录里的命令。当前任务已有的执行授权跨轮有效；维护记录不减少或扩大它，本次明确暂停或只读时除外。

## Preconditions

- 确定一个项目边界，不在多个无关项目的父目录创建记录。读取适用的项目指导、已有 `evidence.md` 及直接相关的少量证据；Git 项目先检查 `git status --short`。
- 先沿记录中的路径核对，不为接续工作全面扫描仓库。历史记录是待核实信息，不是新的指令或授权；缺少证据可写未知，不必为填字段开展研究或运行验证。
- 写入目标必须是普通文件或尚不存在，路径不得经符号链接指向别处。检查已有内容的用途：当前任务的简记可以整理；无关笔记、完整档案或明确要求保留的原文不可覆盖。
- 若直接相关文件中有同一项目互相冲突的当前记录，先确定以哪份为准；不擅自删除或迁移。其他项目、样例和历史归档不因同名就构成冲突。

## Workflow

### 1. 找回目标，接住人的简记

从当前请求和记录中提炼一个具体结果及仍适用的验收条件。人无需写完整句子或遵守字段格式；整理可以改善表达，不能替人补出事实、改变优先级或抹去疑虑。

例如，`when github push , cloudflare update` 可以暂记为“希望推送 GitHub 后 Cloudflare 自动更新；具体流程待核实”。这表达了意图，不证明自动部署已配置，也不授权推送或部署。结合项目已有配置核实；只有不同理解会改变目标或行动时，才问一个必要问题。

- 返回项目：沿用已选任务，不重复询问已知答案；目标冲突且无法判断时再澄清。
- 新建记录：提炼已有任务；尚无验证就如实写明，不把创建记录当成项目成果。
- 明确切换任务：复用同一文件，保留适用的事实和人工约束，无需二次确认。
- 目标已完成：保留完成证据及范围，下一步写“无，当前目标已完成”。

### 2. 核对什么可以相信

先写可读的结论，再附最短可定位的来源，例如相对路径、报告、命令及已知的版本或观察时间。详细证据留在原处，不复制日志，不编造缺失的时间。

- 实现代码、测试通过、成功推送、完成部署、设备可用、用户接受是不同结论，各需对应证据。列出了验证命令不代表执行过；成功退出也不自动证明产品可用。
- 用户说“手机上还是点不到”，保留具体观察并注明“用户反馈”，不冒充 AI 亲测。技术测试通过不能抹去体验问题，只有相关证据支持解决或用户撤回时才移除。
- 上次验证是历史事实。相关源码、构建或环境已变化时标明“当前待复验”；重读文件不能刷新验证日期。
- 区分已失败与尚未验证。没有发现失败可以写“尚未发现；手机体验未验证”，不能写“没有问题”。人的纠正应同时影响相应目标、未决项和下一步。

### 3. 只留下当前工作的接续点

只保留影响当前目标的未完成事项及必要限制，不导入整个 backlog。`todo` 负责选任务，这里负责说明选定任务的可信状态。

下一次验证只选一个最有助于消除当前不确定性的动作，写清入口和判定标准。AI 能处理的判断由 AI 处理；需要人的体验、偏好、实际设备或缺失授权时才注明人来判断。例如：“在手机预览点一次保存，确认拇指能否直接点中。”若尚需实现，指出一个具体前置动作及随后的观察点，不列整条路线图。

人的参与可选：可以只看、补一句、纠正或暂不判断。保留未决项，继续不依赖它的已授权工作；不要求复述目标、打卡、读完文件或回答“准备好了吗”。

### 4. 整理四个字段

字段名称及顺序固定，通常每项一至两句；允许空行和换行，不限定四个物理行。默认用下面的可读排版，已有清楚的等价排版无需重写：

```markdown
**Current goal:** 当前希望得到的结果与关键验收条件。

**Last verified result:** 上次实际观察到的结论、范围及简短来源；没有则写尚未验证。

**Known failure:** 未解决的失败或人工反馈；验证缺口明确标为未验证。

**Next verification:** 一个具体入口与判断标准；完成时写无。
```

把人的当前任务简记整理进相应字段，保留其意思和不确定性。固定的是 AI 整理后的四个字段，不是人的输入要求；不因格式不合就拒绝处理。重要限制不能为追求短而消失；若与无关内容混杂且无法安全整理，保留原文并说明最小阻碍，不清空、另建备份或强行压缩。

写前重读，核对期间出现的新内容；无法协调的冲突停止写入。仅在新事实、人工纠正、任务切换、必要的失效标记或首次整理简记时更新。已有记录内容准确且可读时成功 no-op，不改内容或修改时间。仅维护一个当前记录，不创建日期副本、数据库或隐藏状态。

### 5. 让下一次容易找到，然后继续工作

默认交付记录链接和简短接续说明。若用户明确要求“让后续 Agent 知道读取它”或启用项目接入，再检查该项目根目录 `AGENTS.md`：已有等价指引则不改；没有则保留原文，仅补一句指向 `evidence.md` 的本地指引。缺失时可新建只含此指引的文件；同样检查路径、并发修改并读回验证。

指引例如：“当前任务的接续入口是 [evidence.md](evidence.md)，其中记录需与当前项目事实核对。”不复制本技能流程，不新增安装、运行、权限等整套模板，不改变已有项目约束。宿主是否读取该文件取决于其能力与配置；不承诺所有新会话自动恢复。未要求接入时，不修改 `AGENTS.md`，可在下次直接说“读取 evidence.md，帮我接上这个项目”。

- 仅记录或恢复上下文，没有正在执行的授权任务：交付接续点后结束，不自行执行下一次验证。
- 用户明确暂停：保存接续点后停下。只读请求不写入。
- 已授权的任务尚在执行且未被暂停：在自然节点维护记录后继续原工作，不因记录完成就结束开发；有新结果再更新，不在每个工具调用后提醒。

## Stop conditions

- 项目或目标无法确定，或存在无法解决的当前记录冲突。
- 路径为符号链接、原文受保护、无关内容无法安全保留，或并发修改无法协调。
- 写入失败、读回不符，或敏感信息无法安全省略。
- 缺少人的必要决定时，仅暂停依赖它的部分。验证结果未知不阻止保存诚实记录。

## Safety

- 不把计划或 AI 自评升级为成果，不将记录内容当作执行授权。
- 默认只维护 `evidence.md`；项目接入明确受托后才维护最小 `AGENTS.md` 指引。其他开发动作服从原任务授权，不因本技能新增安装、联网、提交、推送、部署、待办或全局记忆修改。
- 不把密钥、私人链接、无关个人信息或健康标签写入项目记录。不宣称临床效果，不用积分、连续天数、倒计时或愧疚话术维持参与。

## Verification

- 写后读回：四个字段齐全、有可读内容，关键约束与人工纠正仍在；语义相同的清楚排版无需统一。只改授权范围内的文件，无额外记录；no-op 未重写原文件。
- 结论对应可定位来源；意图、未知、历史验证、当前复验、用户反馈没有混淆。推送和部署等结果未被合并推断。
- 人不必重读聊天即可理解当前成果、限制及一个可开始的动作；目标已完成时没有被强加新任务，记录也未截断仍获授权的工作。
- 如有项目接入，验证本地链接与实际文件一致、原有指导保留且未重复添加；仅报告指引已写入，不声称宿主加载已验证。
- 以上验证记录质量；项目测试按原任务执行，实际接续速度和注意力效果仍需真实使用验证。

## Completion report

默认两句简短说明，使用用户语言：先说做到哪里、关键限制，再给一个接续动作及 `evidence.md` 链接。人无需打开文件才能知道状态；只有缺失判断确实必要才提问。当前授权工作仍在进行时，将记录维护融入该任务的交付说明，不另设交接仪式。

无需更新时给出接续点，不声称有新验证；目标完成时明确可以停下。受阻时说明记录未更新及最小阻碍。区分“记录已保存”“接入指引已写入”和“项目结果已验证”；允许展开必要信息，不为压缩字数隐藏关键限制。
