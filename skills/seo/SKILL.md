# SEO

## Outcome

对一个明确目标交付有证据支持的搜索优化结果：已检查的本地内容与配置改动，或只读审查；需要外部配置的项目给出准确字段、目标和值。完成范围是请求中的检查或改动，不以收录、排名或流量上涨作为无法即时证明的完成条件。

## Use when

- 用户要求网站 SEO、抓取或收录排查、搜索结果标题描述优化、规范 URL 或多语言搜索入口检查。
- 用户要求 GitHub 仓库名称、About、Topics、README 搜索表达，或已有包的搜索元信息优化。
- 显式调用 `$seo` 完成本地优化，或 `$seo audit` 只读检查。

## Do not use when

- 只要求 AI 回答理解、品牌提及、来源引用或生成式搜索表现；这些属于 `geo`。
- 只做排版、翻译、Git tag 操作、发布部署、付费投放或泛泛的 SEO 概念解释。
- 用户要从零建站、全站重设计、专项性能调优或链接投放；发现相关问题可以记录，但不接管这些工作。

## Inputs

- 必需：目录、仓库标识或网站 URL。显式目标优先；否则从当前项目判断真实发布入口，不固定偏向 GitHub。有多个冲突候选时仅询问目标。
- 可选：目标受众、搜索语言、查询、指定平台、保护文案、文件范围和真实搜索数据。没有搜索量或排名数据时不编造，用用户意图提出待验证的查询候选。
- `audit` 或“检查、评估、先讨论”只读；“修改、优化、实现”与裸 `$seo` 可修改请求范围内的本地内容。默认不发布或应用远端设置；已明确授权的具体动作沿用原授权，无需重复确认。
- 同时请求 SEO 与 GEO 时，约定同一项目、页面和事实来源：SEO 负责技术与元信息，GEO 负责回答内容与引用证据。同一页面由一个执行者整合补丁，不并行覆盖对方修改；无需为单独运行安装另一 skill。

## Preconditions

1. 检查项目规范、Git 状态、相关源码与配置，保留已有工作。定位内容源、生成流程和生产目标，区分仓库页面、本地预览、正式网站和下载脚本 URL。
2. 核实项目用途、实际能力、发布状态、语言与可用入口。未发布命令、计划功能和授权未知项应如实标明。
3. 按需只读核实当前官方规则及线上状态，复用本轮已核实的来源。离线时使用本地证据并标注时间；认证或连接失败不能证明仓库不存在、页面未收录或内容未发布。

使用第三方审计、框架默认值或社区 skill 建议时，按需读取 [references/implementations.md](references/implementations.md)，区分平台规则、源码行为和经验方法。

## Workflow

### 1. 找到搜索者与目标入口

从请求、现有页面和可用搜索数据确定用户要寻找什么、哪个现有页面应承接。区分品牌查询、用途查询和具体使用问题，不把每个同义词做成新页面。已有文本准确时不为关键词密度改写。

保留少量可执行发现：证据位置、问题、影响的入口、建议改动和验证方法。先处理可访问性与事实错误，再处理入口表达和元信息；按当前目标选择，不要求清单全部命中。

### 2. 按实际平台检查

- **网站**：按需读取 [references/website.md](references/website.md)。检查生产响应与主内容、抓取和索引控制、标题描述、canonical、语言路由、可发现内链以及已有 sitemap / 结构化数据。每项先判断是否适用，不能把“缺少可选标签”直接定为错误。
- **GitHub / 包注册表**：按需读取 [references/github.md](references/github.md)。检查名称、About、Topics、README 和已有包元信息；区分 Topics 与版本 tag。名称贴题时保留，改名须先查分发依赖。不能用本地 HTML meta 配置 GitHub 仓库页面。
- **内容**：自然说明项目是什么、适用谁、真实能力和下一步，修复误导承诺、失效入口与必要的图片文字。保持品牌、默认语言和有效展示；只有本轮确实涉及的语言版本才同步修改。

GEO 相关的答案证据缺口可以记录；只请求 SEO 时不追加一套 AI 提示词评测或强制 FAQ。

### 3. 完成有界改动

审查模式输出具体修正建议，不写文件。修改模式改内容或配置源头，沿用现有组件、框架与生成器，不手改生成物或维护第二套 URL 列表。需要新内容时先核实实际能力，不能用未来计划补满页面。

远端项给出可审阅值及作用目标，例如仓库完整标识与 `description`、`topics`，或具体页面的标题与 canonical。公开仓库、改名、访问控制、提交推送、发布包和部署不由 skill 自动执行；用户已明确授权的动作按原范围执行并读回核实。

无证据支持改动或目标已经满足时返回 `NO-OP`。后续任务仅保留实际障碍；只有用户要求时写入待办，不自动生成长期 SEO 计划。

### 4. 验证交付

检查 diff、受影响语言、链接与锚点、图片、元信息和生成产物。源码配置、构建输出、线上响应和搜索结果分别记录，不能相互替代。文字或视觉布局改动按实际范围检查渲染；仅元数据改动不强行增加视觉审查。

检查原始 HTML 与需要时的渲染 DOM；抽取成纯文本的页面可能丢掉 head、脚本和 JSON-LD，不能仅凭抽取结果断言缺失。工具总分不替代具体检查项、警告与目标爬虫状态。

使用项目已有验证命令，运行与改动相称的构建或静态检查；没有改动生成流程时不重复无关测试。若本次已授权应用远端设置，重新读取准确字段确认结果。

有真实分析数据时比较一致的查询、页面、语言和时间窗口；没有数据就报告已准备的内容或已修正的技术问题，不宣称排名提升。

## Stop conditions

- 目标、生产域名或项目事实冲突会改变结果：暂停依赖部分，完成其他有证据的工作后询问最小信息。
- 需要扩大品牌、公开范围、许可声明、发布行为或访问权限，且现有授权不覆盖：保留具体方案，不跨越边界。
- 工作区重叠无法保留、关键验证失败或结果不明：停止相关写入并核实状态，不靠覆盖、重试外部动作或削弱检查继续。

## Safety

- 不编造热度、评价、客户、背书、许可证、平台兼容性或搜索指标；不保证收录和排名。
- 不堆积隐藏关键词、空提交、营销 tag、无内容 Release 或虚假结构化数据；不把分享封面直接宣称为排名因素。
- 不为抓取而自动删除预览站保护、撤销 `noindex`、公开私有内容或允许所有机器人；核实目标内容与既有规则用途。
- 不安装工具、购买服务或向第三方扫描器上传私有内容。skill 选择不额外授权外部通信与发布。

## Verification

- 每项发现可回溯到文件、生成物、平台状态或标明时间的用户证据，规则与编辑判断分开。
- 搜索意图、可见内容、平台字段、链接及实际能力一致；抓取、索引和认证限制没有混淆。
- 修改的是源头，生成结果反映改动，未覆盖既有工作；远端只报告实际读回的结果。
- `audit` 没有修改目标，`NO-OP` 没有制造工作。检查是否充分，以用户要求的范围为准：离线审查可完成；要求上线效果但缺少线上证据则是部分完成。

## Completion report

报告 `DONE`、`NO-OP`、`PARTIAL` 或 `BLOCKED` 及明确范围，再简述主要发现、改动、验证与少量剩余动作。区分本地已改、远端已应用、待发布、未核实；公开访问、索引记录、查询排名与流量分别陈述。提供必要文件链接和规则来源，不输出没有依据的综合 SEO 分数。
